# Persistent tasks and phase gates

`node src/cli.js tasks <ramp.json>` replays `.ramp/tasks.jsonl` and prints tasks. Add `--event <event.json>` to request a change. Events require `type`, `actor`, and nonempty `reason`; the project ID is bound by the store. Actors are audit labels, not authenticated identities.

A create event contains `task` using `schemas/0.1.0/task.schema.json`: ID, configured owner, scope phase, planned status, question, inputs, expected output, acceptance criteria, evidence references, empty artifacts, and nullable `reopenedFrom`. See `test/tasks.test.js` for a complete executable lifecycle including failed review and a linked reopened task. Run it with `node --test test/tasks.test.js`.

Run `node examples/workflow/run.js <new-directory>` for a synthetic lifecycle demonstration with all phases and a failed review/return to analysis. It records workflow events and explicitly synthetic artifacts; it performs no research or model calls.

A transition event contains `taskId` and optional `status`, `phase`, `owner`, and `artifacts` (`{path, kind}` relative to the project). Gate artifacts must exist inside the project; their normalized content hashes are recorded. Phases advance one step: scope→plan requires charter, then plan, evidence, analysis, review, brief, and delivery artifacts for the respective gates. Starting and unblocking happen before advancement. Entering in_review requires the review phase and an analysis artifact. A failed review can return work to an earlier phase with reason and review artifact. Approved review is required before synthesis; the reviewer supplies outcome, reviewer ID, selfReview boolean, and issues list. Artifact presence does not prove review quality.

Blocked transitions require `blocker` and `unblockCondition`; resuming requires `resolution`. Cancellation requires the event reason. Done requires delivery phase, a delivery artifact, approved review, `acceptedCriteria` explicitly including every criterion, and a complete/partial/blocked `disposition`. That disposition describes research completeness; a partial report can satisfy a task whose criteria allow partial reporting. Terminal records are immutable. A new planned/scope task can reference a completed task through `reopenedFrom`.

The local JSONL journal has sequences, UTC timestamps, previous-record hashes, actor/reason, and artifact hashes. It is replay-validated before every write and read; it detects accidental corruption, not malicious rewriting of the entire chain. Writes use a directory mutex and fsync; another writer gets a retryable busy error. Storage is a local filesystem, not a network/distributed store. A crash may leave a lock or truncated record: recover a backup and investigate before removing a stale lock; RAMP never guesses that another writer is dead or silently repairs history. Historical artifact hashes record what was referenced; they are not a guarantee that current files still match. Keep versioned artifact files for repeatability.
