# Reference host boundary

`ReferenceHost` is a provider-neutral mediation API, not an orchestrator. An external agent framework owns scheduling, model conversations, retries, authenticated identities, and tool implementations. It can request `assignment`, `startCycle`, `requestTool`, `transition`, `checkpoint`, `resume`, `cancel`, and `status`. Assignments supply task state, complete instructions, budget state, and disposition. No model/provider dependency is required.

Construct it with a manifestPath and a trusted tool map. Each tool needs a capability, exact resource/destination allowlist, permitted phases, validateInput predicate, and execute handler receiving `{resource, input, signal}`. Source reads reserve the same canonical resource key across agents; they require an explicitly budgeted cycle in gather/analyze. Review can revisit a committed source, but new acquisition requires returning to a research phase. A failed-review generation needs a fresh cycle. Permission is the intersection of the assignment's declared module requirements, project ceiling, and host's explicit mapping/scope. A persona adds no capability. Unknown tools, scopes, inputs, wrong owners, blocked/cancelled tasks, and failed gates are rejected before execution.

All tool destinations must come from the mapping, not hidden input fields. The host implementer must validate input shape and make its handler use the checked resource. For filesystem tools, explicitly map destinations and enforce realpath containment including symlinks; this reference does not offer an unrestricted filesystem/shell/network tool. Do not expose the host object or mutable tool map to an untrusted model: expose only validated request messages.

Tools cooperate with AbortSignal. A pre-start abort makes no underlying call; begun source attempts consume budget even if cancelled or failed. Cancellation prevents later requests, but cannot undo effects a trusted handler already performed or force an ignoring handler to stop. Budget reservations remain conservative if a process crashes. Journals record request/input/result hashes and outcomes rather than copying tool inputs/outputs or credentials. These local hashes are audit aids, not authenticated identities.

Checkpoint resume persists ownership and selected modules in the shared task journal. A fresh host reconstructs effective configurations from recorded swaps and validates the recorded locks; altered inputs fail. Optional `locked: true` also requires the project's base lockfile. Never discard journals to reset budgets. Local mutex/busy-error limitations apply; independent journal operations are not a distributed transaction. Host cycle reservation and audit append may need operator reconciliation after a crash; they fail conservatively, not by restoring capacity automatically.

Run `node examples/host/run.js <new-directory>` for fake-source/fake-agent requests with one permitted resource and one denied resource, no credentials or external calls. Tests cover denied calls, budgets, state gates, cancellation, persona invariance, and restart at a checkpoint. To integrate another framework, translate its tool messages into requestTool calls, route only returned results to its agents, retain all state journals, and supply trusted scoped handlers. Actions outside this mediation boundary and the model's factual reasoning remain outside its guarantees.
